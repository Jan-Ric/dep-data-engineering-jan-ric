# Dashboard Layout

## Audience

- **Primary:** O&M engineer reviewing flagged inverter periods and deciding which records need follow-up.
- **Secondary:** Plant supervisor scanning fleet status, validation results, and analysis limits.

## Page Order

1. Persistent simulation notice and anchor navigation.
2. Headline question, fleet summary, and definition of a PR gap and the fixed three-hour rule.
3. Four headline KPI cards: flagged inverters, designed faults caught, expected misses confirmed, and false alarm blocks.
4. Fleet status bars for Watch, Alert, and Critical, with counts and suggested first actions.
5. Flagged inverter summary, followed by a collapsed table of all rolling blocks.
6. Full-width planted-fault PR chart and a collapsed table of daytime PR observations for the plotted inverters.
7. Fifteen-window detection validation, including expected misses and any source note text.
8. False-alarm result and its simulated-data caveat.
9. Tier-based suggested actions and collapsed additional metrics.
10. Footer links to the repository, KPI definitions, segmentation, stakeholder brief, and this layout.

## Data and Presentation

The page is generated by `scripts/build_dashboard.py` from `docs/data/dashboard_data.json`. The JSON is produced from the project's saved CSV tables; displayed counts, dates, gaps, PR values, notes, and KPI values are not manually copied into the page. Displayed PR and gap ratios are rounded to three decimal places. Tier badges include their text so meaning is not carried by color alone. Tables are horizontally scrollable on narrow screens, and the navigation links point to sections 4 through 9.

The site is static HTML and CSS. All page links and image paths are relative for GitHub Pages sub-path compatibility. The chart alternative text describes the comparison shown; tables provide the underlying hourly readings.

## Interpretation Limits

The planted faults are controlled demonstrations, not plant diagnoses. The non-faulted inverter comparison shares the same weather and simulated PR, so zero false alarms does not test noisy real data. Overlapping rolling blocks count separately.
