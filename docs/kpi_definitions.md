# KPI Definitions

These metrics summarize modeled inverter-hour data and saved analysis tables. They support descriptive review, not diagnosis of real equipment faults. Throughout the detector analyses, `pr_gap` means the median valid PR across all inverters at a timestamp minus that inverter's PR at the same timestamp. It is not `1 - PR`.

| KPI | Definition and formula | Unit | Source | How to read it | Limitation |
| --- | --- | --- | --- | --- | --- |
| Performance Ratio (hourly, per inverter) | Mean valid hourly PR across inverter-hour rows; each row uses `PR = AC_POWER / (irradiance_kWh_m2 * installed_DC_kWp)`. The saved summary reports the pooled mean. | Unitless ratio | `output/tables/summary_statistics.csv`, processed metrics `PERFORMANCE_RATIO` row | Compare with 1.0 as a normalized reference; the pooled mean describes the modeled daytime fleet, not an individual inverter. | Only positive-irradiance rows have valid PR. The compact source is an aggregate, so this KPI does not provide the hourly series for each inverter. Weather, AC output, and fault windows are modeled or simulated. |
| fleet_mean_pr_shortfall_from_1 | `1 - pooled mean valid PR`; this is distinct from detector `pr_gap`. | Unitless ratio, often shown as percentage points | Derived from `output/tables/summary_statistics.csv` | Distance below the normalized PR reference of 1.0. | Not a comparison to a healthy-fleet baseline and does not establish a fault. |
| Flagged 3-hour block count | Sum of saved qualifying block counts across severity tiers. A block is a rolling set of three consecutive exact hourly timestamps; each hour must have irradiance above 200 W/m² and non-null PR, and the mean of the three per-hour `pr_gap` values must be at least 0.05. | Blocks | `output/tables/flagged_blocks_by_severity.csv`; rule in `sql/03_flagged_3h_blocks.sql` | Counts overlapping rolling windows, so one extended period can contribute more than one block. | Count is based on simulated data and a fixed rule. It is not a count of confirmed equipment failures. |
| Flagged inverter share | `inverters with at least one qualifying block / 830 inverters * 100`. | Percent of fleet | Distinct IDs in `output/sql_results/03_flagged_3h_blocks.csv`; fleet size from `README.md` | Portion of the fleet with one or more qualifying blocks. | Flags are based on simulated data and a fixed demonstration rule, not confirmed failures. |
| Severity distribution | For each tier, `tier block count / total flagged blocks * 100`; report Watch, Alert, and Critical counts and shares together. | Blocks and percent of flagged blocks | `output/tables/flagged_blocks_by_severity.csv` | Shows how saved flagged blocks are distributed by their 3-hour mean gap tier. | Overlapping blocks are counted separately. The sample has no timestamp, so it cannot identify unique clock hours. Clipping is an expected model cap, not by itself a fault. |

## Thresholds

The saved three-hour query evaluates rolling sets of three consecutive hourly timestamps. Each hour must have irradiance above 200 W/m² and a valid PR; the three-hour mean `pr_gap` must be at least 0.05. Severity is Watch for gaps from 0.05 up to but not including 0.10, Alert from 0.10 through 0.20, and Critical above 0.20. These are demonstration thresholds, not validated maintenance limits.

## Detection Result

The regenerated validation detected inverter 202's 2025-06-20 window (mean `pr_gap` 0.06220, Watch). It did not detect inverter 101 on 2025-03-15 (0.01144) or inverter 303 on 2025-09-10 (0.01385). The weaker +4°C and +12°C injections may stay below 0.05 because the simulated degradation term starts only above 45°C internal temperature, making the resulting PR effect small; in this run the +4°C window stayed below threshold while the +12°C window crossed it. This result reflects the simulation design, not a failure of the method.

## Audience

The primary audience is an O&M engineer, who can use the metrics to prioritize records for review and verify the fixed detector against its test windows. A plant supervisor can use the fleet summaries to understand the scale and severity mix of modeled flags. Neither audience should treat a flag as a confirmed fault without real telemetry and investigation.
